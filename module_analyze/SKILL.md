# 模块分析指南

当用户要求分析某个模块（如 GPIO、UART、ADC、定时器、某个业务功能模块等）时，从以下维度进行系统性分析：

## 1. 一句话总结

用一句话概括该模块的主要职责和作用。

## 2. 分层架构分析

将该模块按逻辑分层，逐层说明：
- 每一层的职责是什么
- 每一层使用了哪些硬件资源（寄存器、中断、DMA 等）
- 每一层使用了哪些软件资源（库函数、回调、数据结构等）
- 层与层之间的接口和依赖关系

## 3. 调用链与数据流向（重点展开）

详细分析：
- 该模块的上层调用者是谁（哪个任务、中断、或上层模块）
- 传入参数是什么，参数在各层中的存储形式
- 数据的最终流向（输出到哪里、如何被消费）
- 关键的数据结构定义和状态转换

## 4. 设计评估

- **设计要点**：该模块有哪些值得肯定的设计决策
- **设计缺陷**：有哪些潜在问题（资源泄漏、竞态条件、可维护性问题等）
- **优化建议**：具体可行的改进方案

## 输出格式

分析结果使用中文，结构清晰，必要时用表格整理引脚/寄存器/参数等信息、用美观的时序图和程序流程图来描述流程和数据流向。如果涉及代码引用，给出文件路径和行号范围。
